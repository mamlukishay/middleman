Record

The looper's one red control. It is the base button in every respect — same face, same border, same 30px — until it is running, when it takes the only colour in the app that is not amber, grey or magenta. One key, one button, the whole record → end → overdub cycle.

In its row, where it actually lives
Lit, it is the only thing in the row that has a colour. Undo and Clear stay on the grey face beside it, 8px away, so the red carries the whole state of the deck: the lane is taking your playing right now. Note that #recBtn.on is an id rule, so it beats button:hover — once recording, the button stops answering the pointer, the same way a lit .tgl.on does.
The state that does not exist
.armed is styled and never set. The selector reads #recBtn.armed,#recBtn.on, so the sheet describes two states — armed, and recording — drawn identically in --rec. Nothing in src/ ever adds .armed; only .on is used. So there is no arming step to see, and if one were ever added it would be indistinguishable from recording. Read the rule as #recBtn.on and treat the rest as a leftover: dead CSS that quietly promises a state the app does not have.

Rules. Record is the base button, unmodified, until it is running. It never gets a red rest state, a red border or a red outline — the red appears only while the lane is actually taking sound, which is what makes it worth having a colour of its own. That colour is --rec #e63d40 with white ink at weight 600, and it is the sole exception to “on means amber”, allowed because recording is destructive and amber already means “selected” everywhere else. Like every lit control it drops its hover. Nothing else in the app may borrow --rec for a button, and .armed stays unused unless someone gives it a look that is visibly not this one.
